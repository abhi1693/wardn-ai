= Secrets and LLM Providers
:revdate: 2026-08-09
:page-revdate: {revdate}
:description: Learn how Wardn separates secret backend configuration from provider and tool credentials.

Wardn treats MCP server credentials and LLM provider credentials as sensitive configuration.

[#_secret_backends]
== Secret backends

Secret backends are configured at the organization level. OpenBao credentials are operator-managed through named profiles, not configured directly by organization administrators.

[#_managed_secret_handles]
== Managed secret handles

Wardn stores references to external secret paths instead of exposing credential material directly. Managed secret cleanup is handled by a background worker.

[#_llm_provider_credentials]
== LLM provider credentials

LLM provider credentials authorize model calls. They are separate from MCP credentials, which authorize external tool calls.

[#_outbound_requests]
== Outbound requests

Outbound OpenBao, catalog-sync, and remote MCP requests use a shared SSRF policy. Public HTTPS on port 443 is allowed by default. Internal destinations, nonstandard ports, and plain HTTP require explicit operator configuration.
